# AGENTS.md

Chrys — Python 3.14+ agent platform (TUI + headless CLI + ACP server). Users see it as **iCode**: that is the display name (`foundation/branding.py::APP_DISPLAY_NAME`) and the `icode` command (`APP_COMMAND`); the package, `~/.chrys`, `CHRYS_*` variables, wire/header names and data structures keep `chrys`, which also stays installed as a command. `pyproject.toml` is the source of truth for version/deps.

uv run icode                 # launch TUI; `uv run chrys` is the same entry point (flags: -s/--session -a/--agent -m/--model -C/--workdir)

## Local testing policy
- After implementing code changes, run `uv run python scripts/chrys_test.py --smart --paths <files changed by this task>`. Pass only files changed by the current task so pre-existing user changes do not widen the selection; include deleted paths and both old/new paths for renames.
- Developers may omit `--paths`; Smart Test then discovers committed branch changes plus staged, unstaged, and untracked files.
- A focused pytest node may be run while debugging a known failure, but finish verification with Smart Test. Do not manually calculate the final affected pytest scope: Smart Test owns import, pytest-fixture, architecture-guard, runtime-asset, and local fallback selection.
- After Smart Test passes, do not run the full suite unless the user explicitly requests full local testing or Smart Test escalates automatically. Use `uv run python scripts/chrys_test.py --full` for that explicit local check.
- `--full` means the complete local non-integration pytest scope; it excludes `integration` and `gc_calibration` and is not the cross-platform PR gate.
- Smart Test is a local optimization only. CI/CD keeps its direct complete PR gates and must never use Smart Test to select or skip tests.
- Smart Test favors quick local feedback over exhaustive impact coverage: follow up to two source import hops, narrow ordinary function-body edits using the Git baseline, resolve named static re-exports, skip type-only imports, and include direct test edits, observed fixture consumers, and explicit file watches. Uncertain or unmapped changes use nearby test directories; only global test-environment/configuration changes automatically escalate to `--full`. Distant consumers may be omitted locally and remain covered by CI.
- Ruff, formatting, type checking, i18n validation, and build verification remain separate. Report whether Smart Test or the complete local non-integration suite ran; never describe a Smart Test pass as a full-suite pass.

## Architecture & control flow
- **Bootstrap**: `orchestration/startup.py::bootstrap_runtime(...)` — loads .env, sanitizes proxy, applies foundation/patches, settings via `load_settings()`→`settle_session_root()`→`install_process_settings()` (`Settings.from_env()` is a compat shim production must not use), otel. Every entrypoint calls this; never duplicate.
- **CLI dispatch**: `app/cli/app.py::main()` is hand-rolled (NOT argparse subparsers). Order: `__tui_subprocess__`, version, help, then run/agents/models/install/serve/acp/trajectory; anything else → TUI. Bare `icode` = TUI. Subcommand modules under `app/cli/`; TUI entry `app/tui/app.py::main`.
- **EventBus** (`foundation/events/bus.py`): in-process async pub/sub, the SOLE frontend↔backend channel. `subscribe()` callbacks per Event type (awaited inline → backpressured, never lossy) + `stream(*types)` async-iterator (unbounded per-consumer queue — LOSSLESS by design: a slow consumer grows memory, never drops; dropping would truncate streamed LLM output on the headless/ACP path. One-shot high-water log at `_STREAM_QUEUE_HIGH_WATER` for observability only). `publish(raise_handler_errors=False)` swallows+logs handler errors. Event types in `foundation/events/types.py`.
- **AgentEngine** (`orchestration/engine/engine.py`): long-lived backend owner — session lifecycle, event subscriptions, profile/workspace switch, rollback, mutations, rebuilds, MCP cache. Holds ≤1 `TurnBindings` with a `KernelConversation` backend. Delegates: turns→`run/coordinator.py TurnCoordinator`, build/start→`build/construction.py`+`build/builder.py`, FSM→`state/machine.py EngineStateMachine`, permits→`state/controls.py`. Lifecycle: `start()`/`prepare()`/`shutdown()`; subscribes handlers BEFORE first build.
- **TurnCoordinator** (`engine/run/coordinator.py`): user-message/interrupt/retry/inject, run_fresh/run_retry, finalize, submit-gating. The engine passes ITSELF as host (same convention as rollback/session_lifecycle/sub_agent_coordination); the contract is the per-module `*Host` Protocols (`TurnCoordinatorHost` = union of downstream via Protocol inheritance), enforced by `tests/orchestration/engine/test_protocol_compliance.py` (member-existence + access-set + forwarding-edge guards). Rebuilds swap `_turn_bindings`/backend/middleware in place — phase services re-read host attrs per use, never cache across an await. Also in run/: retry.py, finalizer.py, runner.py, active_injection.py, turn_state.py.
- **Turn execution**: `engine/run/bindings.py::TurnBindings` owns middleware wiring, presentation flags and the pass observer; `run/resume.py::TurnResumePolicy` anchors inputs and constructs requests. `begin_invocation()` allocates identity and clears prior outcome/evidence before fresh preparation; `fresh_request()` uses that identity. Retry uses a ticket only while `KernelConversation.continuation_is_live()` confirms identity, generation and origin; invalidated tickets are consumed and the Turn continues from history. Admission errors, including promotion-to-bind failures, set failure flags and enter normal finalize/save/release without replay; retry input restoration still exits its request body normally. `invoker/kernel.py::KernelConversation.run(RunRequest)` owns pass admission, outcome, evidence and cancellation; `invoker/attempts.py::AttemptRunner` drives L0 `agent.run()` attempts through the sole `AttemptTaskHandle`. `engine/execution.py::ExecutionLease`, composed by `TurnRuntimeState`, owns the top-level task, admission, drain and final-save evidence. Retry ownership splits by storage mode: local → kernel `WireRetryPolicy` per wire call in place; service-side → whole-run `StreamRetryLoop`. Both use the effective transient budget (`CHRYS_MAX_TRANSIENT_RETRIES`, else frontend default; backoff 3/7/15/30/60s); response-validation retries stay independent (stored mode: budget-exempt lane); streaming falls back to blocking after stall exhaustion, and that fallback's budget SPLITS BY STORAGE MODE: local → the kernel streaming wire lane calls `_blocking_response_with_retry()` inside the SAME `agent.run()` and starts a fresh transient counter, so one logical provider call can make up to N+1 blocking attempts (per-call local-streaming worst case 3N+2 provider calls, pinned by `tests/kernel/test_wire_retry.py`); service-side → `wire_retry_policy` is None (TurnBindings passes one only when NOT service-side; loop.py also drops it on `storage.service_side`), so `AttemptRunner._stream_with_retry` exhausts `StreamRetryLoop` and starts exactly ONE blocking `agent.run()` fallback attempt outside that loop, with no fresh transient retry budget. That blocking model/tool loop may still make multiple provider calls; "one" describes the fallback attempt, not a provider-call bound. Do not "fix" the service-side path by adding a retry lane — whole-run semantics own it. `PassResources.begin()` fires the main `run_cycle_start_hooks` and child `pass_start_hooks` inside the backend pass try; validation budget resets stay at pass entry, never between attempts. With no operation binding, owner close cancels the complete pass, including observer waits, and pairs only its own cancel with uncancel; with an operation binding, the shell remains responsible through final-save. `Ok.backend_payload` preserves the raw response; `structured_output` is left None for caller policy, without eager validation.
- **Sub-agent caller shell**: `sub_agents/shell.py::SubAgentToolShell` is the sole child `OperationBinding`, owns the human decision future and invocation-wide `InvocationEvidence`, and publishes pause/resume/abort/cascade facts. `KernelSubAgentPolicy` and `AcpSubAgentPolicy` retain backend-specific result, audit and cancellation policies without independent pause loops. Policies read shell state through `tool_name`/`agent_name`/`bus`/`owner_close_cause`/`status`/`cascade_requested`; recipes bind the one-shot parent commit with `bind_parent_interrupt_commit()`. ACP passes its cancellation-safe drain to `await_cascade_publish()`; the shell does not depend on ACP protocol code. Tool recipes keep quota, controller registry, writer, hooks and live approvals alive through operation drain; pending records are removed only after parent save succeeds. `AcpConversation` alone owns transport attempts, monotonic `transport_ordinal`, teardown and late-update accounting. Closing during translator adoption must not spawn a new client; an aborted ACP operation rejects later passes without rewriting its cause. A registry built with `human_failure_decisions=False` (headless chat, every workflow node: the graph, node transcript and headless run show no per-child card) never pauses a failed child — the shell ends it as aborted at once, `abort_result(by_user=False)` returns `Error: sub-agent 'X' failed — …` to the caller's model, and no pending record is written; only TUI/ACP chat children pause for the card's Retry/Abort.
- **Invocation event routing**: main and child execution/presentation facts use `Invocation*` with a required, sealed `InvocationOrigin`. `invoker/origin.py::invocation_routing_key` locates a registered emitter for shared-client callbacks; capture the emitter before awaiting and never repair origin from ambient context. `TurnBindings.finished()` clears its local emitter and registry entry. Approval argument edits and context pressure use the same family, so child edits reach their own cards. Caller/request correlation protocols retain their explicit allowlist; persisted `sub_agent_invocation_id` metadata and external ACP method/payload shapes remain unchanged.
- **builder.py::build_agent(...)** → `AgentBuildResult` (prepared, conversation, agent, bindings, runtime SessionEnvironment, loop_recorder, reminder_middleware, sub_agent_tools, mcp_adapter, skills_provider, tool_names/tool_kinds, skill_names, memory_files, runtime_details, compaction_strategy, active_profile, profile fingerprints) from an AgentProfile.
- **ChrysSessionHost** (`orchestration/session_host.py`): wraps one bus+engine+session for non-TUI (CLI run & ACP). `iter_run_events` (raising, CLI) vs `iter_turn_events` (non-raising, sets last_turn_outcome for ACP). Headless `run` uses `ApprovalMode.BYPASS`, `allow_user_interaction=False` (QuestionToUser fails fast); ACP passes `True`.
- **ACP server** (`app/acp/server.py`): translates ACP JSON-RPC → ChrysSessionHost; non-standard caps via `ext_method` (inject/mutations/diff/rollback/switch_agent/...). **stdout = JSON-RPC ONLY**; logs→stderr via `app/cli/acp.py::_configure_logging` (StreamHandler(sys.stderr), WARNING). Never print to stdout in ACP path. Every non-interactive subprocess (including startup/version/Git/platform probes) MUST set `stdin=DEVNULL` explicitly on every OS; ACP stdin is the JSON-RPC pipe and inheritance can block or consume protocol bytes—use `PIPE`/`input=` only when the child intentionally receives input (the workflow worker host is such a child: its stdin is the protocol channel, spawned via `spawn_managed_stdio_process`). Client-supplied MCP HTTP headers are LITERAL (never resolve `{{ENV_VAR}}`); client stdio/SSE rejected. Deep ACP spec/gaps: `app/acp/doc/frontend-api.md`.

## Conventions & lint footguns
- **Docs follow features**: any change that adds, alters or removes user-visible functionality updates the affected `docs/` pages in the same change, in both `en` and `zh-Hans` (see **User guide** below).
- File header EXACTLY: `# Copyright (c) Huawei Technologies Co., Ltd. 2026. All rights reserved.` then blank line then `"""docstring"""`. Match on new files — except builtin workflow templates (`service/workflows/builtins/*.py`), which users copy: they open with a one-line `#` description and no copyright.
- Async-first across event/engine/invoker/tool/host paths. `asyncio.get_running_loop()` not `get_event_loop()`.
- **Cross-platform**: branch on `foundation.platform.get_platform()` (shell/config-dir/OS/path) — never raw `sys.platform`/`os.name`. Code must import on Windows: keep POSIX-only symbols (`SIGKILL`, `killpg`…) inside platform-guarded bodies, not module scope.
- **Windows waits never occupy executor threads**: the default executor is `min(32, cpus + 4)` threads (6 on a 2-CPU CI runner); anything that parks a thread per wait — Textual's stock timer sleep (`run_in_executor(WaitForMultipleObjects)`), a `to_thread(WaitForSingleObject)` process wait — fills the pool, queues every `to_thread` behind it, and blocks the loop thread in `Thread.start` growing the pool (the mechanism behind the `windows/*/tui` 20–30 s stalls). Register handles with the loop's completion port instead: `loop._proactor.wait_for_handle(handle)` (`IocpProactor`, the wait asyncio uses for subprocess exit) — `foundation/patches/textual_win_sleep.py` for timers, `foundation/platform/process.py` for process handles. Rules for that wait: the handle must stay signalled after completion (manual-reset timer, not synchronization); closing a handle under a registered wait is undefined, so cancel by re-arming the timer to fire at once and close only after the future completes, `Future.cancel()` (synchronous `UnregisterWaitEx`) only when the re-arm fails; and every post-cancel settle wait is BOUNDED (`_REARM_SETTLE_SECONDS`) — an unbounded loop on a port that stops delivering makes the task uncancellable and wedges `Runner.close()` in `_cancel_all_tasks` past both pytest-timeout and faulthandler. Tests never hand a made-up handle to a real proactor: registering an invalid handle is a fatal `0xC000070A` in the thread pool (the xdist worker dies, no traceback), so stub `get_running_loop` on the module under test through a shadow `ModuleType`.
- Public shell-filter API imports go through `service/tools/builtins/shell_filter.py` (facade), NOT the `shell_command_filtering/` impl package.
- **NO getattr/hasattr on first-party types** — direct attr access on dataclasses/Protocols; getattr only at external/SDK boundaries. Add a typed field/Protocol instead.
- Tool params: `Annotated[type, "description"]` (drives schema gen). Modern types only: `X|None`, `list[X]` — never Optional/Union/List/Dict (UP). `from __future__ import annotations`.
- **TUI dynamic text**: wrap ALL system/profile/model/tool/user/file text in `rich.text.Text(...)` / `Content.from_text(..., markup=False)` / `textual.markup.escape(...)` — plain str is treated as markup, bad `[` → MarkupError. **`markup=False` is REQUIRED**: bare `Content.from_text(value)` under the TUI root is guard-rejected (`test_test_hygiene.py`), since Textual defaults `markup=True` and routes to `from_markup()`. Use `Content.from_markup(...)` only for intentional markup. Only hardcoded markup raw.
- **TUI theme colors in Rich styles**: Textual tokens such as `ansi_yellow` are invalid in Rich style strings. Never interpolate `app.theme_variables` into a Rich style string. Convert plain color tokens through `app/tui/util/rich_style.py::rich_style_from_textual_color`; resolve composite values such as `auto 60%`, alpha colors, and text-style values through a component class and `get_component_rich_style()`; alpha needs fully resolved styles, not `partial=True` (see `ToolCardHeader._zone_style` in `app/tui/widgets/chat/tool_call.py`).
- **i18n pipeline**: after any `msg()` definition change — including moving a definition to another module, since the POT records each definition's source file (path only: `#:` carries no line numbers, so edits that merely shift a `msg()` line leave the catalogs fresh) — run `extract` → `update` → `compile` → `check` twice and require byte-idempotency; NEVER run it concurrently with pytest. `locales/` holds POT+PO only; compile writes the TRACKED `src/chrys/foundation/i18n/_catalogs/zh-Hans/LC_MESSAGES/chrys.mo`. `check` gates source/POT/PO freshness and PO semantics; `tests/foundation/i18n/test_catalog_oracle.py` gates semantic PO↔MO parity and stdlib loadability of the tracked artifacts, AND pins a hardcoded catalog oracle (exact id set + count; the id literal lives in `tests/foundation/i18n/_catalog_oracle_ids.py`) — adding or removing a `msg()` means bumping that oracle in the SAME commit, or the suite goes red even though every pipeline command exited 0. `pseudo` generates only an untracked, non-user-facing en-XA layout-pressure MO and refuses repository destinations.
- **i18n authoring**: only direct module-level `msg("dotted.lower.key", fallback="...")` assignments after canonical `from chrys.foundation.i18n import msg`. Fallback is the exact English display text; catalog strings are plain text, NEVER Rich markup. Placeholders are named `{slot}` fields and must match translations exactly — except `{count}`, which any singular/plural form may include or omit; plural definitions add `plural_fallback=` and bind with `count=...`.
- **i18n scope/hygiene**: localize user-facing DISPLAY prose only. Protocol/model/tool/MCP text (including `Error: `-prefixed tool results), serialized session-marker literals, logs/traces, debug surfaces, ACP output, and CLI entry-point output (help text, tables, run/install stderr) stay English. `_SRC_HYGIENE_RULES` in `tests/architecture/test_test_hygiene.py` bans raw English at TUI notify/border-title/widget-label/placeholder/tooltip sinks and non-canonical `msg()`/Binding construction; the rules and their justified-exception allowlists live in the family modules it registers (`tests/architecture/test_hygiene_tui_prose.py`, `test_hygiene_tui_bindings.py`, `test_hygiene_i18n_messages.py`).
- Footguns: `except (A,B):` → ruff strips parens, don't re-add. `datetime.now(UTC)` not naive (DTZ). No `print()` in source (T20; allowlisted only installer.py). `raise X from err` (B904). No mutable default args (B006). `subprocess.run(check=...)` explicit (PLW1510), argv as list (S603/S607). No busy-wait `while: await sleep` (ASYNC110).
- Tool errors for UI must start `Error: `. `ruff` ignores E501,RET504,S101,S104/5/8,S110,PLW0603,PLW2901,ASYNC109,ASYNC240.

## Supply chain & version pinning
Mutable refs are code execution on the next run, with no PR and no diff — third-party code is pinned to immutable ids so every bump is a reviewed diff. Never loosen a pin to unblock something.
- **Actions**: every third-party `uses:` = full 40-char SHA + trailing `# vX.Y.Z` (tags AND branch heads move; `docker://` pins by `@sha256:` digest — image tags move too). Guard: `tests/architecture/test_workflow_action_pins.py`; only local `./…` refs are exempt. Pinning freezes the fetcher, not what it downloads at runtime, nor nested `uses:` inside a composite action.
- **Selector-branch trap**: `dtolnay/rust-toolchain@stable` / `taiki-e/install-action@cross` use the REF NAME as an input default. Pin the main line AND pass it explicitly (`toolchain: stable`, `tool: cross`), or the job hard-fails at release time.
- **Python deps**: `[project]` + optional-extras use exact `==` unless a documented exception requires a range — ranges re-resolve for whoever installs the published wheel, where our lock does not apply. There are two published range families (five specs total), each explained in-file: `pyjwt[crypto]` (floor only, so mcp's range can float) and the four-package `opentelemetry-*` release train (bumped together). The `pillow` comment instead records an upgrade ceiling tied to the glibc 2.17 wheel floor. `[dependency-groups]` never reaches `Requires-Dist`, so ranges there are fine — `uv.lock` pins and hashes them anyway.
- **`uv.lock` holds the sha256s for the transitive closure**: commit it in the SAME commit as any dep change (CI's `uv sync` has no `--locked`, so drift re-resolves silently). Version bump = `pyproject.toml` + `uv.lock` + `Project-Id-Version` in POT/PO. No Dependabot yet — upgrades are manual.

## Subsystems quick-ref
- **Profiles**: builtins `service/profiles/agents/builtins/{Code,QA,Explore,General}.yaml`, fixed hex ids. Code/QA main-eligible; Explore/General `sub_agent_only:true`. ## Top gotchas
- System reminders: per-turn context appended as trailing `<system-reminder>` on LAST user msg (SystemReminderMiddleware, shallow-copy per call). NEVER put per-turn data in system prompt (KV-cache) or persisted history.
- Streaming: raw updates are yielded before finalization, but the FINAL loop/agent response reuses the kernel loop's assembled Message objects (single reconstruction authority — `_finalize` swaps `response.messages` to the loop assembly; agent `_finalizer` copies the container, element identity preserved). Do NOT reintroduce a `from_updates` re-merge for message content downstream of the loop: it rebuilds multi-fragment function calls as new Contents and drops kernel-stamped provenance (`_chrys_tool_invocation_order`/`_chrys_tool_kind`/`_chrys_tool_context`/`_chrys_tool_result_metadata`). Mid-stream update consumers still see fragments — anchor side effects there via role+call_ids+content-signature, never identity-only.
- **call_ids and message_ids are NOT unique** (replayed/provider-limited histories reuse call_ids; `msg_N` message_ids are positional — compaction re-mints ids that still exist inside archived `compressed_msgs` blocks): pair calls↔results per exchange via `kernel/exchanges.py`, never a global call_id scan, and never use `message_id` as cross-source identity. Identified sub-agent audits deduplicate archived/live occurrences only by `_chrys_analytics_item_id`; content matching is a conservative best-effort fallback reserved for legacy audits without occurrence identity.
- **Sub-agent audit replay**: the authoritative contract is the module header in `service/session/sub_agent_transcript.py`. New kernel audits explicitly declare `analytics_item_id_v1` and deduplicate archived/live twins only by `_chrys_analytics_item_id`; never use `message_id`, `call_id`, or content as occurrence identity. Audits without the capability remain best-effort legacy input, and every new removal rule needs a paired equal-content-survival test.
- **Tool ordinals & result metadata**: the kernel loop is the SOLE AUTHORITATIVE producer of `_chrys_tool_invocation_order` for production transcripts, stamped on every non-informational function_call at response arrival (invalid/unknown/filtered calls consume ordinals too); event middlewares may fall back to local follower counters ONLY in direct-pipeline harnesses that bypass the kernel loop, never to reconstruct persisted order. NEVER count function calls to reconstruct order or re-associate result metadata by position; order-matching consumers read the stamp and fail closed when absent. Result metadata rides `FunctionInvocationContext.metadata`, folded into the result Content at construction. Supporting invariants:
  - **Exchange grammar** (`kernel/exchanges.py`): `iter_exchanges`/`pair_results`/`PairingPolicy`/`is_result_only_message` over a `MessageAccessor` (`LiveAccessor` for kernel messages, `DictAccessor` for serialized mirrors) are the ONLY transcript walkers — hand-rolled result-block/sibling walks in src are AST-banned (`tests/architecture/test_test_hygiene.py`). All of a response's tool results fold into ONE tool message after its complete message list; pairing is exchange-scoped with a shared per-key cursor (one result occurrence consumes one call occurrence — replay/resume presentation), while completeness consumers use the `answered_keys` id-SET view (one result answers every same-id call — never count occurrences); image generation pairs on `image_id`; result-only assistant messages carry tool output (empty assistant shells do NOT — they stay siblings); `HistoryMarkerKind.KEY` assistant messages are hard boundaries. Reuse `TOOL_CALL_CONTENT_TYPES`/`TOOL_RESULT_CONTENT_TYPES`, never redefine.
  - **Weak identity** (`kernel/identity.py`): id()-keyed cross-boundary memos hold WEAK identities — membership requires the object still alive, so no memo strongly retains its keys and a bare id() outliving its object can never false-match fresh work. `WeakIdentityRegistry` backs the kernel memos (echo, fragment/assembly) and summary-cache tiers; exclusion/injection anchors hold raw `weakref.ref` tuples; compaction's `_state_correspondence` is a frame-local bare-id dict rebuilt per call (never outlives the lists it indexes). Exception: `_process_update`'s per-pass `seen_contents` stays STRONG deliberately. `Message.contents` is a weakref-able `ContentList`; each copy site's fresh-vs-shared layer contract is pinned in `tests/architecture/test_copy_freshness.py`.
  - **Echo removal**: a content OBJECT the conversation already holds is removed from the landed response before recording/dispatch. Identity-only (a different content reusing an echoed call_id is fresh work) and non-mutating (containing message shallow-copied). Coverage lives at the pipeline's final-handler boundary, beneath every middleware and per call attempt: `request_message_observer` registers the actual post-middleware request; `_prepare_provider_request_messages` re-registers the exact wire list after below-middleware preparation (observer forwarded only to `_PreparedRequestObserverClient` inners); `_strip_echoed_update` filters streamed updates there too (stream merge mints NEW objects that launder identity past the memo), dropping echo-emptied shells via per-message `_chrys_echo_content_stripped` provenance, never a call-wide flag. Usage content is exempt everywhere — request-scoped accounting a client may legitimately reuse.
  - **Wrapper isolation**: Message wrappers are never shared loop↔client — landing keeps `_message_snapshot` copies; every outgoing message (caller history included, and re-viewed at the final provider boundary AFTER request preparation) goes as a `_wire_message_view` (canonical in `kernel/client.py`, re-exported by loop.py): fresh wrapper + fresh contents list, SHARED content objects (the identity currency) and SHARED additional_properties (the sanctioned write-through channel). `InjectionMiddleware` retains structural copies, never wire objects; a middleware-prebuilt `MiddlewareTermination` result Content is copied per invocation (call_id rebound; stamps land on the copy).
  - **State↔wire matching**: shared content-object identity is the ONLY stable state↔wire currency; every consumer matching wire messages back to state needs a content-identity tier (exclusion/injection anchors, compaction's `_state_correspondence` — else id-less views vanish from `_resolve_turns` and prior-turn compaction silently disables — and cached-summary fold detection). Weak references make stale tiers safe rather than eagerly cleared: `bind_state` clears only the cached-summary pins at the run boundary; exclusion anchors are consume-once and may survive an interrupted run; `_state_correspondence` is rebuilt per call.
- **Transcript guard (keep green)**: `tests/support/transcript_invariants.py` is the structural oracle for kernel-loop final transcripts — one consecutive invocation-order run, no echoed-object duplicates (non-usage Content or Message — a request-scoped usage object may legitimately repeat), exchange-scoped result pairing across ALL call/result content types incl. hosted MCP (one answer per pairing id per exchange, type-aware: image generation pairs on `image_id`, everything else on `call_id`; ids may recur across exchanges; tool output rides tool-role OR result-only assistant messages, and a call-carrying assistant message registers its calls before its embedded results are checked). Tests build or derive from `InvariantCheckedToolLoopLayer` from that module instead of a raw `ToolLoopLayer`; a hygiene rule (`tests/architecture/test_test_hygiene.py`) bans bare construction AND subclassing — import-alias-aware — outside an explicit allowlist, `tests/kernel/test_transcript_invariants.py` pins the oracle's own red/green paths, and `TestTranscriptInvariantFuzz` in `tests/kernel/test_loop_echo_normalization.py` drives seeded adversarial echo clients against it (one parametrized case per seed — the failing seed is in the test id). If the transcript contract legitimately changes, update the oracle's documented invariants and their failure-path pins together — don't weaken assertions ad hoc.
- **Workspace cwd**: resolve relative paths via `SessionEnvironment.cwd`/`Workspace.primary_cwd` (foundation/models/), NEVER process cwd. Applies to approvals, hooks, MCP cache keys, mutations, events. `os.getcwd()` only for one-shot CLI UX.
- **Surrogateescaped paths (POSIX)**: filesystem-derived paths may contain lone `\udcXX` surrogates. The raw `str` is the ONLY form that round-trips to the original filesystem bytes: preserve it in `SessionEnvironment`, `Workspace`, `SessionMeta`, restore state/in-process events, and subprocess `cwd`. `foundation.platform.files.surrogate_safe_text` creates display text that names a DIFFERENT path; use it only on a derived copy immediately before model/API/display output or other non-identity-bearing strict UTF-8 encoding. Identity-bearing serialization/hash keys must encode the raw value injectively (e.g. JSON `ensure_ascii=True` or encoded `os.fsencode` bytes), never use `surrogate_safe_text` — otherwise a raw `\udcXX` path aliases a real literal `\\udcXX` path. MCP hashes raw config with ASCII JSON but spawns with the raw cwd. Never assume callers already normalized input.
- All chrys_history mutation goes through `SessionHistoryManager` (service/session/history.py) — single owner. Markers use `_chrys_kind` in additional_properties: `turn`/`summary`/`interrupted`/`awaiting_sub_agents` (`foundation/models/history_markers.py`).
- **Turn boundaries**: `foundation/models/turns.py` is the SOLE turn-resolution entry point (`opens_turn`/`turn_slices`/`current_turn_start`/`is_injected_message`/`is_continuation_message`). Mid-turn injections carry `_injected` (creation-time flag in additional_properties, never serialized to the wire); **`_continuation` is legacy-only** — the synthetic continue-nudge is no longer created (retry commit points replaced it); the flag and its predicates remain solely for reading old persisted sessions. New code must NOT split turns on raw `role=="user"`, match `"continue"` text, or mint new `_continuation` messages.
- **Late injection is deliberately not relooped**: an injection either reaches the next tool-loop call, or — if the run has already finished — finalization drains it as `consumed=False` and the frontend restores the text to the input box. A completed `agent.run()` is terminal: do not add a Turn/backend follow-up run to deliver a late injection.
- **Injection transaction invariant**: one chat-middleware drain = one immutable batch, registered for retry replay before the first callback `await`; consumed injection messages are carried across later tool iterations as clean middleware-owned copies (never the reminder-enriched wire list).
- **Retry commit points**: any ANSWERED non-interrupted result slot is an IRREVOCABLE commit point (monotonic journal; fills commit synchronously at the side-effect boundary; arg-invalid/unknown-tool/failed results commit too — only synthetic interrupted fills don't); whole-run auto-retry must preserve committed work — never replay a committed tool call. Provider-hosted exchanges (hosted MCP, hosted shell) never reach the loop recorder — the validation middleware is the evidence carrier (`hosted_commits` on the retryable error + run-scoped/in-flight observation probes): in-place validation replays give up instead of re-sending, and the whole-run gates and kernel wire replay refuse to re-create a request after hosted work unless a live continuation token makes the retry a poll-resume; read-only hosted work (search, code interpreter, image generation) is deliberately exempt. Storage mode gates retry style via `kernel/client.py::resolve_storage_mode_and_handles`: OPTIONS are the wire truth (`extra_body` over named param; a present `store: null` selects the provider's storage default), client kwargs may only ESCALATE to service-side — EXCEPT a client's `FORCES_STATELESS` ClassVar (forced-stateless dialects, e.g. DeepSeek Responses), threaded as the resolver's `force_stateless` flag by all nine callers, which vetoes service-side regardless of options/kwargs and additionally strips `continuation_token`/`background` spellings from the sanitized views; service-side storage forbids in-place wire retry (whole-run semantics + continuation-token learn/poll-resume), local mode allows it.
- **Validation retry budget**: `ResponseValidationMiddleware` carries service-mode retry count/reason on the INSTANCE. Lifecycle resets happen ONLY at cycle/pass starts (`TurnBindings` main hooks / `KernelSubAgentPolicy` child hooks through `PassResources.begin()`, both fired inside the try so a raising hook lands on the normal error/pause path); the middleware additionally resets itself when a validation cycle CONCLUDES (valid response, give-up, terminal raise); NEVER reset between whole-run retry attempts within one cycle. Service-mode give-up is ALWAYS terminal (the service holds unscrubbed conversation state). Client-mode validation retries back off inside the middleware and are visible only via `publish_retry` (`InvocationRetryAttempt`, with explicit origin and retry scope) — dropping that wiring = silent UI stalls during backoff.
- **Reasoning replay (chat-completions) is dialect-driven, NOT provider-driven**: the base client replays `reasoning_content`/`reasoning_details` unconditionally — Kimi runs on the plain `openai` provider and requires preserved reasoning_content, so replay cannot be scoped by provider; native api.openai.com is safe because it silently drops unknown message-level fields before tokenization (live-verified: no 400, zero token cost) even though top-level params stay strictly validated. Capture provenance rides the `openai_reasoning_format` marker — an unknown-but-present marker contributes NOTHING on replay — and `protected_data` is a per-provider format: any new writer must audit every consumer (openai_chat_completion, openai_responses, deepseek, anthropic_chat).
- **Reasoning-bearing assistant serialization** (`_prepare_reasoning_assistant_message`): tool results are run separators; each run's reasoning rides that run's string-content aggregate (never a result record); reasoning-only runs defer FORWARD past contiguous result blocks; non-text fragments emit standalone AHEAD of their run's aggregate. DeepSeek delegates this path to the base — its schema rejects assistant content arrays.
- **Plain-walk wire shape**: the base chat client emits fragment-per-content and flattens text-only content lists to plain strings, so mixed histories reach the instrumented canonicalizer as str/list fragments; the canonicalizer merges per kernel message and keeps the tool_calls carrier LAST — unmergeable content-only fragments insert BEFORE it so tool results stay adjacent to their carrier.

## Persistence & TUI
- config_dir = `~/.chrys` (macOS/Linux), `%APPDATA%/chrys` (Win); data_dir==config_dir. Sessions root via `resolve_sessions_dir()` (override `CHRYS_SESSION_ROOT_DIR`).
- Layout: `sessions/<short-id>/session.json` + `.bak` + `session.recovery.json` sidecar. Locks under `sessions/.locks/`. Subdirs created by owners: snapshots/, mutations/, compactions/, approvals/, doc_converter/, tool_results/, otel/, trajectory/, sub_agents/.
- **Crash-recovery sidecar** `session.recovery.json`: same envelope but NEVER in .bak/snapshot heal chain; primary write deletes it. Readers primary-only; `prefer_recovery=True` only after active-lock owned.
- **Startup session restore is transactional:** `-s/--session` prepares engine subscriptions without building the default agent, while seeding the selected startup profile as the fallback for legacy sessions whose persisted profile is blank. Restore succeeds only after observing the matching `SessionRestored` event — a facade returning normally is not proof because `EventBus.publish()` may swallow backend handler failures. Before fallback startup, suppress persistence while tearing down any partially installed Turn bindings/backend, workspace, session id, and lock; then reset to a fresh-session baseline. Also clear the TUI's restoring state when cancelling the restore so fallback `SessionReady` handling is not skipped.
- TUI: a package owning ONE top-level screen uses `screen.py` + `screen.tcss` (main/, diff/, logs/, models/, sessions/); feature packages name the module after the feature (agents/config.py+config.tcss, settings/dialog.py+settings.tcss); dialogs/ is one `<name>.py`+`<name>.tcss` per dialog; menus/ ships no .tcss. Secondary screens live beside the owner (diff/rollback_modal.py, models/picker.py, agents/picker.py) — the name is a convention, nothing enforces it. MVVM Textual-native (reactive/watch/data_bind/Message). main/ heavily decomposed (controllers/ports/presenter/view_adapter); ports are Protocols in `screens/main/ports.py` (narrow, no concrete widgets). Widgets must NOT define or RUNTIME-import Screens or `screens.*` — `if TYPE_CHECKING:` imports are permitted and used. chat replay/toc must not runtime-import textual or sidebar widgets. Inline `DEFAULT_CSS` on reusable widgets; .tcss for screens. `terminal/emulator/` is a Textual-free VT emulator (parser/buffer/core/input) — it must not import Textual or the widget; `terminal/rendering.py` turns its rows into strips, `pty_process.py` is the cross-platform PTY seam (`PtyProcess` Protocol; POSIX fd vs ConPTY), `shell_integration.py` owns the per-shell OSC 2025/2026 hooks (the import rule is guarded by `test_tui_structure.py`). Program input is `str` end to end; a byte that is not text (a default-format mouse coordinate ≥ 128) rides in it as the `surrogateescape` lone surrogate, which only the POSIX writer turns back into the byte (`"ignore"` there re-breaks wide terminals) and ConPTY drops. `widgets/diff_view/`: `rows.py` lays hunks out as typed `DiffRow`s, `cells.py` draws gutter cells as pure functions shared by the scrolling columns (`GutterColumn`/`CodeColumn`) and the single-widget `UnifiedDiffLines`, and the palette is resolved per look (theme + console color system) while painting — a theme flip repaints in place, never recompose for it.
- **Large-history replay:** keep planning detached from mounting, precompose the detached widget forest before Textual registration, then register/mount in bounded batches so the message pump can render progress and remain responsive. Do not replace this with per-entry mount/layout work. Report restore progress through the loading UI from completed top-level entries, not through per-batch event-log messages. Batch size is a profiling-tuned implementation detail, not a fixed contract.
- **Intermediate text persistence/replay:** persist `_intermediate_text` by the exact `batch_id → anchor message` mapping, never by positional scans, and do not write a sidecar when the same text is already visible in that anchor's contents. Replay has a deliberately narrow compatibility shim for old sessions whose buggy writer shifted an identical sidecar onto an adjacent batch; it must not cross user/non-tool boundaries and should be deprecated once those sessions no longer require support.
- **Large-session TUI performance (non-GC):** any App-wide stylesheet update, restyle, recompose, or layout is O(the entire mounted transcript) and is user-visible at hundreds of widgets. GC tuning cannot fix these stalls. Focus/blur, opening/closing an overlay, changing a binding, or hiding a small panel must not invalidate, restyle, or lay out MainScreen's transcript unless its geometry or styles genuinely changed. Make reactive/state setters idempotent and do not emit refresh/binding/style work for unchanged values.
- **Periodic timers park while not composited:** a `set_interval`/`auto_refresh` timer on permanently mounted chrome ticks whether or not anything is painted (each tick was an executor hop on Windows). The compositor maps neither `display: none` nor `visibility: hidden` widgets, and both Textual's reflow and Chrys's layout-free `set_widget(s)_visibility_without_layout` post Show/Hide from that map difference, so gate animation timers on Show/Hide (`timer.pause()`/`resume()`, a paused Textual timer sleeps nothing) — `ChrysLoadingIndicator` and `BuddyPanel` are the templates; a widget mounted inside a hidden container never receives Show, so its first tick parks the timer itself. Keep polling timers whose job is noticing out-of-process changes (the buddy reload). New timers on always-mounted widgets need a parked-while-hidden test.
- **A retained thread object retains the App:** `Thread.__init__` keeps the `sys.stderr` of that moment, and while an App runs that is its print capture, so whatever outlives the App holding a thread (a native extension's callback, a module registry) holds its whole widget tree. watchdog 6.0.0's macOS FSEvents extension never releases its `add_watch` callback; `foundation/patches/watchdog_fsevents.py` hands it a weak forwarder (unpatched, every MainScreen test leaked its App — up to 15M objects / 2 GB in one xdist worker). Find heap growth with `gc.collect()` + `len(gc.get_objects())` per test; Textual's bounded style/strip caches plateau and are not leaks.
- **Screen CSS locality:** discovering a secondary Screen's CSS must not call `stylesheet.update(app)` on native TUI or otherwise restyle the underlay. Keep Screen selectors scoped/local and preserve the version-gated `ChrysApp._load_screen_css` behavior that reparses new rules but updates only the new Screen; web and MainScreen startup intentionally use Textual's upstream path. Do not add new dynamic/global CSS loading without a populated-transcript regression proving the underlay receives no style/layout pass. Theme changes get one required global pass: fold Chrys class changes into it (`update_classes(..., update=False)`), never trigger extra recursive restyles.
- **Footer/binding hot path:** Textual Footer recompose removes/remounts `FooterKey` children and can relayout the full transcript. Never call `refresh_bindings()` unconditionally on focus changes or no-op state updates. `ChrysFooter` deduplicates the visible binding signature; queued callbacks must be generation-invalidated before equality checks, commit only the post-recompose live signature, run in Footer message-pump context, and recompose only while its OWNING Screen is current (the gate is screen identity, not MainScreen — DiffScreen mounts one too). Changes stranded under an overlay are replayed by that Screen's `on_screen_resume()`.
- **Hiding widgets:** for ordinary show/hide that should remove a widget from layout, use the canonical `widget.display = False/True` (or CSS `display: none`), not a `-hidden`/`-visible` class, `visibility: hidden`, or a new `.visible`/`.is_visible` shadow flag. Class/visibility toggles keep or restyle layout participation and have caused full-screen recalculation on large sessions. Use `visibility` only when deliberately preserving geometry and document that exception; hot fixed chrome must use `set_widget_visibility_without_layout()` to synchronize compositor maps and immediately move focus out of hidden subtrees without full layout. Reserve maximum steady-state widths for labels/buttons whose text or presence changes frequently, and keep any semantic convenience property derived from the canonical display/visibility state rather than a divergent shadow flag.
- **Focus and overlays:** native App focus changes retain the focused widget and must not replay Textual's global focus/style/binding refresh; web keeps upstream behavior. Suspended/covered MainScreen widgets must not recompose or relayout behind overlays. Modal first-open work must be screen-local and heavy I/O/render preparation must occur asynchronously after the loading shell paints.
- Performance regressions for these paths need a real `App.run_test()` with a populated transcript and real events (focus/blur, `pilot.click`, push/pop Screen); handler-direct unit tests are insufficient. Pixels prove output; spies prove absence of layout. Use real geometry when geometry is the contract. Assert the affected subtree/result and pin that MainScreen `update_node_styles`, Footer recompose, and full `_refresh_layout` are not called on no-op/background paths.
- Textual message dispatch checks `prevent_default()` BETWEEN MRO classes; within each class, private `_on_*` wins over same-name public `on_*`. `event.stop()` only stops bubbling to parents; it does NOT stop sibling/base MRO handlers on the same widget.
- In `_on_*`/`on_*` handlers, never call same-name `super()` unless you first `prevent_default()` or have verified the delegated base handler sets it for every handled path. If you manually perform a base/default action (e.g. `super().press()` instead of `super()._on_click(event)`), call `prevent_default()` yourself.
- Button-like click affordances that consume a click and post their own message/action must call both `event.prevent_default()` and `event.stop()`, not just `event.stop()`. Prefer `ClickAffordance` for `Static`-based pseudo-buttons (copy/view/scroll chips). Deliberately selectable widgets/regions may leave default selection behavior enabled when they do not consume the click. Reactive watchers (`_watch_*`) are different: they are looked up once via normal attribute resolution and do not MRO-dispatch like messages.
- Race-free Textual rebuilds: make handlers async, `await remove_children()`, and `await container.mount(*new_widgets)` in one batch instead of fire-and-forgetting per-child mounts. Pruning parents silently reject mounts: return actual attachment and recheck prerequisites after acquiring structural locks.
- **Deferred Textual work:** Signal retains the subscribed callable; unsubscribe does not cancel queued deliveries. Phase isolation: unsubscribe, enqueue a same-pump barrier without an intervening await, check acceptance, then await it. `call_after_refresh`/`call_later` return bool; rejected scheduling must release pending state. Fence stale callbacks when they can commit or clear newer state.
- **Screen ownership:** `dismiss()` resolves the future, queues the result callback, then pops the stack TOP. Guard with `screen is app.screen`; cleanup follows resource ownership, not callback timing. Loading/Buddy animations use `is_widget_shown_on_active_screen()`; cached visibility alone includes covered screens. Async draft snapshots yield to newer input, including whitespace; `load_text()` resets the cursor.
- **Textual defaults:** `_running` belongs to MessagePump. DEFAULT_CSS self-selectors name their defining class; descendants inherit scope. Non-default stylesheets override DEFAULT_CSS even with default `!important`; Screen inline CSS is scoped, CSS_PATH is not. Input selects all on focus by default; set selection explicitly in typing tests.
- GC-freeze UI contract: a renderer that mounts substantial stable content after the normal turn terminal posts `GcAbsorbRequested(STABLE_CONTENT_MOUNTED)` after its final update/prewarm. Terminal UI completion is not the backend boundary: the App hard-gates every freeze action while `AgentEngine.is_turn_lifecycle_active` is true, covering session persistence and after-turn hook draining; never replace this with the earlier-idle FSM/UI flags. Callers resolving an equal-turn persistence race retain `AgentEngine.turn_lifecycle_task` for that exact turn rather than awaiting a later replaceable task chain. Permanently mounted mutable/cache-heavy surfaces implement `GcFreezeParticipant`; Markdown/diff cyclic LRUs delegate through the `ChatPanel` aggregate, and new dynamic cyclic caches must stay inside the measured F4 retained-byte budget or join that aggregate. Destructive removal of a substantial previously stable subtree posts idle `GcReclaimRequested(STABLE_CONTENT_REMOVED)` only after its awaited removal completes. Real theme changes request idle `GcReclaimRequested(THEME_UPDATED)`, not an absorb. Calibration action latency includes every deferred full `MainScreen._refresh_layout` scheduled by cache renewal; `GcFreezeActionMetrics.duration_ms` alone is not a user-visible latency measurement.
- Rich-render test traps: inside `App.run_test()` Textual's stdout proxy reports a tty, so a helper `rich.Console()` emits ANSI even under `capture()` — build assertion consoles with `Console(force_terminal=False, _environ={})`. Table/grid cells pad to column width WITH the cell's own style — `rstrip()` segment text before exact `(text, style)` compares.

## Testing rules
Enforcement labels apply to individual clauses, never a whole bullet: **[AST]** = `_HYGIENE_RULES` rejects source; **[runtime]** = `tests/conftest.py` fails the running test; **[partial]** = only the named shape is guarded; **[review]** = prose only, CI will not stop a violation. A new AST hygiene rule must live in a `tests/architecture/test_hygiene_*.py` family module (all of which `_RULE_MODULES` in `test_test_hygiene.py` scans, and whose in-module allowlists each need an `@_pins_allowlist` liveness test once they hold an entry) and be registered in whichever of `_HYGIENE_RULES`, `_SRC_HYGIENE_RULES` or `_GLOBAL_SRC_HYGIENE_RULES` matches what it scans; a focused non-AST architecture guard, such as the test-file line cap, stays a standalone `tests/architecture/test_*.py` module instead. Either way it must be proven able to go RED under the real `-n 8` addopts, not only pytester `-n0`. A guard that can't go red is worse than none — it is believed.

| Contract | Enforcement |
| --- | --- |
| Ignored shared `wait_until` results | **[AST]** |
| Local polling helpers / fixed sleeps / counted settles | **[partial]** helper-name blacklist only; structural clones are **[review]** |
| Direct `AgentEngine(...)` + `.start()` | **[AST]** |
| Engine lifecycle completion before post-run state reads | **[review]** |
| Environment restoration; non-integration network isolation | **[runtime]** |
| Quarantine metadata and expiry | **[AST]** + **[runtime]**; eligibility and failure-signature isolation are **[review]** |
| Git/port/background-work/path-domain/test-double contracts below | **[review]** |

- **Waits**: positive waits use `tests/support/waiting.py::wait_for`; `wait_until` is only valid when its bool result is asserted or branched on (**[AST]**). Poll the asserted condition with a deadline; no fixed sleeps or `range(...)`/`pilot.pause()` polling, even with `break`. Bounded `asyncio.sleep(0)` turns may exercise known scheduler interleavings, but must not serve as readiness/completion waits. Neither sleep nor Pilot establishes future quiescence. If a producer can fail early, wait for `ready.is_set() or task.done()`, await a finished task to expose its error, then assert readiness. Engine-turn waits pass the explicit `ENGINE_TURN_TIMEOUT`; when a multi-stage path's per-call maxima would consume teardown headroom, share one `ENGINE_TEST_WAIT_TIMEOUT` via `with_wait_deadline` instead of summing them. That decorator starts at test-body entry: async fixture setup and all teardown remain outside its clock, so the shared budget must leave room for both under pytest's per-test timeout. To assert absence over time, use a bounded `assert not await wait_until(...)`; quiet probes pass a concrete `description` to `wait_until_quiet`. File/module default wait budgets must be strictly below the global per-test timeout and leave time for diagnostics and teardown; explicit budgets are not platform-scaled. Don't add local polling helpers (**[partial]** name blacklist); extend waiting.py. Never replace `asyncio.sleep` on the `asyncio` module itself (`waiting.py` polls with it: a non-yielding double starves every background task and turns a wait into a 5 s spin); stub the module under test's own `asyncio` name through a shadow `ModuleType`. A test that leaves a task which cannot finish cancellation hangs pytest-asyncio's `Runner.close()` in teardown, where neither pytest-timeout (`thread`) nor `faulthandler_timeout` fires — `kill -ABRT <pid>` gets the stacks. CI disks stall plain writes for seconds under fsync pressure: a root autouse fixture widens `RUN_RECORD_WRITE_ACK_TIMEOUT_SECONDS` (a missed run-record ack fails the run as storage-failed, unlike the session trajectory's graceful degrade), and tests of that bound pass `write_ack_timeout` to `WorkflowRunStore.open` explicitly.
- **Pilot waits:** stock `Pilot._wait_for_screen` (behind every `pause`/`press`/`click`) barriers only the messages queued when it starts, then trusts a CPU-time idle probe that a descheduled runner or Windows' 15.6 ms process clock satisfies at once, so handler-posted work (a bubbling `Pressed`, a dismissal's screen swap, idle-forwarded layout) can still be in flight; a pump's look-ahead also parks the next message in `_pending_message`, where `qsize()` reads 0, and a pump takes a message off its queue BEFORE running its handler, so an empty queue with no callback pending still means nothing while the loop is off its `Queue.get` wait. The root autouse `_settled_pilot_waits` (`tests/support/pilot_barrier.py`, pinned to Textual 8.2.7) repeats the barrier until the App and current screen hold nothing and every pump is parked at its queue (`is_parked` reads the pump task's await chain). Workers, tasks and timers are not messages (a Screen lays out from its update timer): still `wait_for` the asserted state. **[review]** Arm no-layout/no-restyle spies only after `screen_is_settled(app, screen)`, not `screen._layout_required` alone: queued messages and widget-level layout requests reach the screen after that flag reads clear.
- **Textual test seams [review]:** dispatch caches reset between tests, not within them. Patch base handlers before dispatch through a fresh local subclass; instance handler spies are bypassed. Negative handler assertions need a positive dispatch control. `Static.render()` returns Visual: use `rich_plain`/`rich_segment_lines` or strips. Outside `tests/app/tui`, Chrys widget harnesses need `TuiVariableDefaultsMixin`; theme overrides preserve its defaults. For recoverable workers use `exit_on_error=False` and own `worker.wait()` errors; default worker failures also reach the App.
- **Authoritative completion**: wait for the lifecycle boundary that owns the state. Engine tests inspect post-run state only after `await engine.wait_for_run_task()`; model call counts mark request START, and final frontend events may precede persistence. Serial authoritative timeouts still share one end-to-end test budget: their summed maxima must stay below the effective pytest timeout with diagnostic/teardown headroom, or the file needs a documented timeout override. Use the `agent_engine` fixture (**[AST]** direct-start ban), which guarantees reverse-order shutdown.
- **Background ownership**: every task/thread/worker/timer/signal subscription/subprocess has an owner and deterministic teardown. Await/join/cancel and restore temporary subscriptions; don't make a test green by globally quiescing or detaching the production path it claims to test.
- **Path domains**: declare whether a value is a raw filesystem identity, Git's POSIX path, serialized identity, or display text before normalizing or comparing it. Preserve raw surrogateescaped filesystem paths for identity; never route them through display normalization. Capability-probe filesystem behavior instead of assuming separator, case, newline, symlink, or filename semantics.
- **Flake fixes**: state the causal mechanism and prefer a deterministic scheduling/fault-injection reproducer that fails before the fix and passes after it. If no seam exists, record the platform, worker topology, seed, and repeated stress evidence. Scan and report same-shape sites; raising a timeout alone is not a root-cause explanation.
- **Quarantine**: only confirmed flaky behavior may use `@pytest.mark.quarantine(reason=..., expires="YYYY-MM-DD")`; repeated deterministic failures are not flakes. The reason identifies owner/issue and expected failure signature. Bare/expired metadata fails CI, but current non-strict xfail does not isolate new failure modes, so quarantine results require separate review.
- **Test doubles**: production-call replacements use `autospec`, a typed Protocol, or an explicit signature contract. Do not add unconstrained `**kwargs` merely to absorb future production parameters; every intentionally ignored argument remains explicit.
- **Middleware contracts**: keep ≥1 engine-driven test per kernel↔middleware contract (tool-loop reminder enrichment, profile switch). Porting an engine test to direct middleware calls while keeping its name is silent coverage deletion.
- **Env/network**: use `monkeypatch.setenv`, never raw `os.environ[...]` writes (**[runtime]** leak guard). Temporary phases use `monkeypatch.context()`, never mid-test `.undo()` on the shared fixture. Outside fixture lifetime, own a `pytest.MonkeyPatch()` and `.undo()` in teardown. Egress beyond loopback — connect/connect_ex, UDP sendto/sendmsg, create_connection, and DNS-by-name via getaddrinfo/gethostbyname — is blocked at configure time. External network tests need `@pytest.mark.integration`; `tests/integration/` contains OFFLINE cross-layer tests and must not be marked integration.
- **Working directory**: every test starts in its own empty directory (autouse `_isolated_working_directory`), never the checkout; reach repository files through `__file__`, not the process cwd. `tmp_path` is a constant-time override without pytest's numbered-directory sweep.
- **Git/ports**: use `git_repo_factory` (hermetic committed template, auto-maintenance disabled); hand-rolled repos can leave `git maintenance` racing the test. Servers bind port 0 and hand over the listening socket (or publish a polled port file); stopped-server tests keep a socket bound-but-not-listening. Never free-port-probe then reconnect.
- **File size**: every Python file under `tests/` — `test_*.py`, `conftest.py` and private helper modules alike — is capped at 2,000 lines by `tests/architecture/test_test_file_size.py`. Split an oversized file by subject or scenario, never merely to get under the number; add an exemption to `_OVERSIZED_EXEMPTIONS` only when the file is the only one covering its single subject and is long because that subject is inherently large, with a specific inline reason saying why splitting it would make the tests worse.
- **Coverage claims**: a symbol grep is not coverage evidence — trace production call paths and test the boundary the data actually crosses. A green unit test on a helper can coexist with production bypassing it. Mutation proofs use scoped memory patches or isolated checkouts; never restore whole-file snapshots over concurrent edits.
